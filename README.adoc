= Antora `example$` Kroki demo

A small, self-contained Antora project that demonstrates resolving *Antora resource ids
(`example$…`)* in the Kroki PlantUML extension — both as a `+plantuml::+` block-macro target and
inside PlantUML `!include` / `!includesub` directives.

It accompanies the IntelliJ AsciiDoc plugin change for
https://github.com/asciidoctor/asciidoctor-intellij-plugin/issues/516[asciidoctor-intellij-plugin#516]
(refs #489). The Kroki server has no filesystem access, so every `example$…` include must be
*resolved and inlined* before the diagram is sent — that is exactly what the plugin now does in the
IDE preview, mirroring the official `asciidoctor-kroki` JavaScript extension.

The same problem exists when `@antora/pdf-extension` (Antora Assembler) renders PDFs with the Ruby
`asciidoctor-pdf -r asciidoctor-kroki`: the Ruby gem knows nothing about Antora resource ids. This
repo ships a small Antora extension, link:extensions/antora-assembler-kroki.js[`extensions/antora-assembler-kroki.js`],
that closes the gap for the PDF export — see <<pdf-export>>.

== What it covers

`docs/modules/ROOT/pages/index.adoc` exercises, in order:

. *Block macro + shared-layout include* — `+plantuml::example$order-model.puml[]+`, whose `.puml`
  does `!include example$layout/colors.puml` and `!include example$layout/legend.puml`.
. *Reusing the shared layout* in a second diagram (`order-lifecycle.puml`).
. *`[plantuml]` delimited block* form with `!include example$layout/colors.puml`.
. *`!includesub`* with a named sub-block — `!includesub example$roles.puml!Core` (the section
  itself includes the shared layout, so nested includes are inlined recursively).
. *Pass-through* — `!include <C4/C4_Context>` is _not_ an Antora id, so it is left untouched and
  resolved by the Kroki server. Remote `http(s)` includes are passed through the same way.

== Two ways to use it

=== A. Live preview in IntelliJ (the feature)

. Install the patched plugin build (`asciidoctor-intellij-plugin`, branch
  `feature/kroki-antora-resource-ids`).
. Open this folder in IntelliJ and open `docs/modules/ROOT/pages/index.adoc`.
. In *Settings ▸ Languages & Frameworks ▸ AsciiDoc*, enable the *Kroki* diagram renderer and set a
  server URL — either the public `https://kroki.io` or a local Kroki, e.g. `http://localhost:8000`.
. The preview renders all five diagrams; the shared `colors`/`legend` layout proves the `example$`
  includes were inlined.

[[b-build-the-reference-site-node-antora]]
=== B. Build the reference site (Node / Antora)

For the PDF export step you also need Ruby installed, with the `asciidoctor-pdf` and
`asciidoctor-kroki` gems on `PATH` (`gem install asciidoctor-pdf asciidoctor-kroki`). The HTML site
itself only needs Node.

[source,sh]
----
npm install
npm run build
----

Open `build/site/index.html`. This builds with the official `asciidoctor-kroki` JS extension, so it
is the reference rendering the IDE preview should match. The PDF export lands at
`build/site/kroki-antora-example/_exports/index.pdf`.

[NOTE]
====
The build reads from `branches: HEAD`, so it needs at least one git commit. If you unzipped this
rather than cloning it, run `git init && git add -A && git commit -m init` first.

Diagram rendering needs network access to `https://kroki.io` (or change `kroki-server-url` in
`antora-playbook.yml` to a local Kroki server).
====

[[pdf-export]]
==== PDF export and `example$` ids

`antora-assembler-pdf.yml` runs plain `asciidoctor-pdf -r asciidoctor-kroki`. Antora Assembler expands
`include::` directives and rewrites xrefs and images, then pipes the merged AsciiDoc to that Ruby
process — and the Ruby `asciidoctor-kroki` gem has no notion of Antora resource ids. Without help,
every `+plantuml::example$…[]+` macro fails with "Failed to read plantuml file" and every
`!include example$…` reaches the Kroki server unresolved.

`extensions/antora-assembler-kroki.js` (registered under `antora.extensions` in the playbook) fixes
this on the Node side. It wraps the Assembler's page loading and, only for Assembler exports, rewrites
each page before it is merged: a `+plantuml::example$model.puml[]+` macro becomes a `[plantuml]` literal
block containing the diagram with all includes inlined, and `!include example$…` lines inside
`[plantuml]` blocks are inlined in place. It reuses `asciidoctor-kroki`'s own JavaScript preprocessor
and Antora adapter, so `!includesub`, nested includes, `!include_once`, cycle detection and `<stdlib>`
pass-through behave exactly as on the HTML site. The regular HTML build is untouched.

NOTE: One gap remains on the HTML site. `asciidoctor-kroki` 0.18.x resolves `example$…` for block-macro
targets (and everything they `!include`), and AsciiDoc `include::example$…[]` directives inside a
`[plantuml]` block are expanded by Antora itself. But a PlantUML `!include example$…` written directly
inside a `[plantuml]` block gets no page context in the kroki block processor, so the adapter cannot
resolve it and the line is silently skipped (the third diagram renders without the shared layout on
the site). The IDE preview and the PDF export both resolve it.

The PDF converter needs Ruby. Without a local Ruby toolchain, run the build in a container that has
Antora, asciidoctor-pdf and both `asciidoctor-kroki` variants, mounting this directory as the
playbook dir; the extension resolves `asciidoctor-kroki` from `node_modules` or `NODE_PATH`.

=== C. Standalone `.puml` preview (JetBrains PlantUML integration plugin)

The AsciiDoc preview above resolves `example$…` itself. To open a `.puml` file _directly_ with the
separate *PlantUML integration* plugin, raw PlantUML can't resolve `example$…`. The
link:.plantuml/README.adoc[`.plantuml/`] directory bridges that gap with alias symlinks.

Its *Included paths* setting is global to the IDE and takes the *absolute* path of this
directory (`<checkout>/.plantuml`) under *Settings ▸ Tools ▸ PlantUML integration ▸ Included paths*.
A relative entry does not resolve against the project root. See
link:.plantuml/README.adoc[.plantuml/README.adoc] for details.

== Layout

[source]
----
docs/
└── modules/ROOT/
    ├── pages/index.adoc        the demo page
    └── examples/
        ├── layout/colors.puml  shared skin, included via example$layout/colors.puml
        ├── layout/legend.puml  shared legend
        ├── order-model.puml    class model + shared-layout includes
        ├── order-lifecycle.puml
        ├── roles.puml          !startsub Core/Roles library
        ├── roles-simple.puml   !includesub example$roles.puml!Core
        └── context.puml        !include <C4/C4_Context> pass-through
extensions/
└── antora-assembler-kroki.js    Antora extension: inline example$ ids for the PDF (Assembler) export
.plantuml/                       aliases for standalone .puml preview (outside docs/, ignored by Antora)
├── example$layout       -> docs/modules/ROOT/examples/layout
└── example$roles.puml   -> docs/modules/ROOT/examples/roles.puml
----
